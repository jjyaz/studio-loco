# Feature module rules (src/lib)

- Arbitrage math lives in `src/lib/arb-math.ts` (pure, exact BN) and chain composition in `src/lib/arb.ts`; round trips are one atomic tx built from raw `swap2` instructions, never the SDK `swap()` helper, because that helper unwraps/closes the WSOL account between legs.
- Dispatch scan/requote work runs through `src/lib/job-control.ts` (single-flight lock, monotonic generation, bounded steps, drain latch) — timed-out RPC promises cannot be aborted, so new jobs must wait for them to settle.
- Liquidity Agents logic is split: pure rules/triggers/review-freshness in `src/lib/agents.ts`, SDK/API composition in `src/lib/agents-chain.ts`, practice fixture in `src/lib/agents-practice.ts` — keeps money-guard logic testable and practice data out of the live builder.
- Signal Box: pure tick rules in `src/lib/signal-box.ts`, worker in `src/lib/signal-worker.server.ts` behind the token-checked hook `src/routes/api/public/hooks/signal-tick.ts`, commits only via the `signal_commit` DB function — revision/status/expiry are re-checked atomically so paused/edited/deleted watches drop in-flight results. Commits also require the caller's unexpired worker lease (`_holder`). Watch mutations are compare-and-swap on revision. The VAPID seed lives in the private DB schema (service-role-only `signal_push_seed()`), push endpoints are restricted to real browser push providers, and the service worker builds its own navigation from a validated alert UUID.
- Flight Recorder records are written by the shared runner (`useTx.tsx` → `src/lib/recorder-store.ts`) — every route gets evidence without per-page wiring; records never contain RPC URLs or signed bytes.
- Rebalance Planner pure identities/ranges/assumptions live in `planner.ts`, read-only unsigned builds in `planner-chain.ts`, and UI in `RebalancePlanner.tsx`. Comparisons, detailed options and selections are immutable new Recorder facts, never executable imports. Same-pool reviews may explicitly widen; pool moves remain separately approved withdrawal/deposit stages with linked evidence. Preserve source range/active, form, rule/watch and wallet identity invalidation, 120s comparisons, 20s reviews, fee caps and JobControl drain latches. `asyncSemanticGuard` verifies current private watches before signing and after wallet approval; unknown/changed watches discard the signed transaction before broadcast.
- Journey Continuity: strict local strategy/chapter/stage contracts in `continuity.ts`; named installed-IDL instruction roles in `continuity-proof.ts`; read-only independent transaction/account verification in `continuity-chain.ts`. Shared runner prepared facts never include bytes/signers and are not verified chapters. Capture only local facts + confirmed local wallet records; imported/cloud/manual records cannot be promoted. Moves require retained reviewed destination intent, verified source withdrawal, matching owner/mints, and independently verified deposit. Never infer lineage from a URL/plan ID alone, nor closure from absence alone. Protect original/stage/closure receipts during retention; enforce stored-row CAS, immutable ancestry/origin/chapter contents and nondecreasing confirmations. SDK continuity contracts are generated by `scripts/generate-continuity-contract.mjs`; regenerate before SDK builds and preserve prior immutable download archives. Local export analysis never authenticates supplied chain history and is unavailable on public HTTP MCP.
- Switchyard contracts and deterministic range-policy replay live in packages/sdk/src/switchyard.ts and are shared by the app. Score pre-decision ranges only; never infer continuous time-in-range, inventory, fee income or PnL. Stored source/policy/retained samples are immutable and CAS checked. Pause/read-failure gaps suppress first-reset actions. Imports remain isolated paused supplied evidence. Commit decisions durably before their virtual range can affect later observations; Recorder copies must not overwrite conflicting facts or acknowledge temporary storage. Source Journey writes must not recreate removed watches. Local latest decisions only can hand off IDs to fresh Planner comparison; revalidate retained scope/freshness before and after wallet signing. Hosted MCP never registers private-history analyzers; preserve older SDK downloads.
- Conductor v1 contracts/evaluators live in `packages/sdk/src/conductor.ts`. V1 feasibility previews remain unsigned and non-executable; separate v2 budgets/guards authorize only supported fresh wallet reviews. Per-operation token top-up caps are not cumulative reservations or deployed-inventory ceilings. Preserve `executable: false`, missing native cost/cooldown evidence and existing station review boundaries. Shared export analysis recomputes supplied history without chain authentication; its MCP tool is opt-in local stdio only.
- Conductor chain reads use a fresh isolated SDK pool, standard SPL mints, verified bin PDAs/pool binding and one <=9-key pool/mint/clock/bitmap/bin account context, bounded to two arrays per direction. Partial/unavailable quotes never imply zero depth. Fee-exclusive average deviation uses active-bin Q64 integer cross-products; BOTH SDK LP `fee` and `protocolFee` count toward trading fees in their actual input/output currency. Owner funding and Journey LP inventory use separate disclosed contexts. Timeouts stop subsequent work and preserve the JobControl drain latch. Durable mission history uses stored-row CAS, immutable policy versions, disclosed retention/gaps and commit-before-Recorder copying. Never promote an exported report into transaction permission or attribute all pool depth to an LP.
- Conductor operations: cumulative unsigned contracts in `packages/sdk/src/ledger.ts`, strict supplied-only analysis in `ledger-evidence.ts`, durable financial state in `ledger-store.ts` sharing the v2 mission database. Reserve/CAS/check/delete are atomic across missions/budgets/operations. Never reset consumed or unresolved liabilities across revisions, free ambiguous signatures on timers, import executable operations, truncate financial history or confuse per-operation top-up caps with cumulative budgets. Native verified actions originate only in `conductor-execution.ts`; `conductor-execution-proof.ts` checks every installed-IDL account/recipient/instruction and excludes token top-ups, arbitrary programs, approvals/closes, staged transactions and rewards. Shared `tx.ts` hooks finish before signing and before broadcast. Keep policy, budget, scope, exact message, native costs/reserve and 20-second reviews checked on both sides of wallet approval. Durable signed metadata precedes broadcast; receipt reconciliation accounts gross owner funding plus fee, including charged failed-transaction fees. Hosted/imported evidence is never a permission source.
- Hosted Conductor: `conductor-hosted.functions.ts` derives account IDs from authentication; explicit consent before upload. `conductor-observer.server.ts` uses the verified adapter with a server-only read-source resolver; browser retained Journey checks remain intact. Signal Box's existing cron/lease drives mission reads; commits go through service-only `conductor_observer_commit` with exact policy/revision/lease/status/expiry/counter checks. Preserve RLS, shared five-watch quota, 60-sample retention/omission disclosure and sampled-vs-current freshness. No hosted signer or automatic financial action.
- The Depot: pure launch/review/challenge/gate rules live in `src/lib/depot.ts` (no SDK, no network); DBC/DAMM v2 chain composition must stay in a separate module and send only through `tx.ts` — keeps money rules testable.
- Depot launch linkage is accepted only via `depot-launch.server.ts`: rebuild the exact original launch message and byte-compare the confirmed receipt, then `depot_link_launch` CAS; never accept client-supplied launch fields.
